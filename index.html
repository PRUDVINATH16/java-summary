Chapter 3: Arrays, Strings & Inheritance

3.1 Arrays (Exam Ready)

An Array is a container object that holds a fixed number of values of a single type. The length of an array is established when the array is created. After creation, its size is fixed.

Array vs ArrayList (2-Mark PYQ)

  • Size: Arrays are fixed; ArrayLists are dynamic (can grow/shrink).
  • Data Types: Arrays can hold primitives and objects; ArrayLists can only hold objects.

Jagged/Irregular Arrays (8-Mark PYQ)

A multidimensional array where each row can have a different number of columns.

int[][] jaggedArr = new int[3][];
jaggedArr[0] = new int[2];
jaggedArr[1] = new int[4];
jaggedArr[2] = new int[3];

3.2 Strings & StringBuffer

Creating Strings:

  1. By string literal: String s = "welcome"; (Created using double quotes).
  2. By new keyword: String s = new String("Welcome"); (Using the String class constructor).

Important Methods (PDF Wording)

  • length(): Returns the length of the string.
  • charAt(i): Returns the char at position i.
  • equals(t): Returns true if the two strings have equal values, otherwise false.
  • compareTo(t): Compares strings lexicographically. Returns a positive number (if s1 > s2), negative number (if s1 < s2), or 0 (if equal).
  • toString(): Returns the String representation of the object. If you print any object, the compiler internally invokes this method.

String vs. StringBuffer

  • String: Represents fixed-length, immutable character sequences.
  • StringBuffer: Represents growable and writable (mutable) character sequences.
Exam Tip: StringBuffer Capacity
By default, capacity is 16. If the number of characters exceeds the current capacity, the new capacity is calculated as: (oldcapacity * 2) + 2.

3.3 Inheritance Basics

Inheritance is the mechanism of deriving the properties (methods, variables) of one class into another class. The keyword used is extends, which means to increase the functionality.
  • Super Class: The class whose features are inherited (base or parent class).
  • Sub Class: The class that inherits the other class (derived, extended, or child class).

Types of Inheritance

  1. Single: Subclasses inherit features of one superclass.
  2. Multilevel: A derived class inherits a base class, and acts as a base class to another class.
  3. Hierarchical: One class serves as a superclass for more than one subclass.
  4. Multiple: Java does not support multiple inheritance with classes (causes ambiguity in hybrid inheritance). Achieved only through Interfaces using the implements keyword.
  5. Hybrid: A combination of more than one type of inheritance.

3.5 Constructors & the super Keyword

Order of Execution: In inheritance, the constructor of the base class is executed first, then the child class constructor.

3 Usages of super:

  1. Refer immediate parent class instance variable.
  2. Invoke immediate parent class method.
  3. Invoke immediate parent class constructor (super()).

3.6 Method Overriding

If a subclass provides the specific implementation of the method that has been declared by one of its parent classes, it is known as method overriding.

Rules:

  1. The method must have the same name.
  2. The method must have the same parameters.
  3. There must be an IS-A relationship (inheritance).

3.7 Abstract Classes & final

  • Abstract Class: Declared with the abstract keyword. It can have abstract and non-abstract methods. It cannot be instantiated (cannot create an object).
  • final Variable: Acts as a constant (value cannot be changed).
  • final Method: Prevents Method Overriding.
  • final Class: Prevents inheritance further (cannot be extended).


Chapter 4: Interfaces & Packages

4.1 Interfaces Fundamentals

An Interface in Java is a blueprint of a class.
  • Methods are abstract by default (declared but not defined).
  • Data members are public, static, and final. They must be initialized with a constant value.
  • An interface acts like an abstract class; you cannot instantiate it.

Why do we need Interfaces? In C++, multiple inheritance causes ambiguity (hybrid inheritance issue). Java does not support multiple inheritance with classes. Instead, it is suggested to use interfaces.

Extends vs Implements (Valid/Invalid):

  • Class extends Class (Valid)
  • Class implements Interface (Valid)
  • Interface extends Interface (Valid)
  • Interface implements Class (IN-VALID)

4.2 Multiple & Nested Interfaces

Multiple Interfaces: A single derived class acquires the properties from multiple base interfaces.

class ClassName implements Interface1, Interface2 { ... }

Extending Interfaces: One interface inherits the abstract methods of another interface.

interface Interface2 extends Interface1 { ... }

Nested Interfaces: Defining an interface inside another interface.

class ClassName implements OuterInterface.NestedInterface { ... }

4.3 Packages Fundamentals

Packages are a way of grouping related classes, interfaces, and subpackages together to organize code, prevent naming conflicts, and manage access control.

Advantages (6 Points): Uniquely Compare Classes, Easy Search, Reuse Classes, Avoid Naming Conflicts, Provide Controlled Access, Implement Data Encapsulation.

Types: Built-in packages (java.lang, java.util, java.io) vs. User-defined packages.

Compilation & Execution:

javac -d . Simple.java
java mypack.Simple

4.4 Import vs Static Import

  • Standard Import: import pack.*; imports all classes, but not subpackages.
  • Static Import (1.5+): Access the static members of a class directly without the class name. Example: Math.sqrt() becomes sqrt().
Exam Tip: Static Import Disadvantage
Static import makes the program unreadable and unmaintainable if reused heavily in large codebases.


Chapter 5: Exception Handling & Concurrency

5.1 Exception Hierarchy

  • All exceptions must be a child of Throwable.
  • Error: Thrown by JVM, represents internal system errors (e.g., OutOfMemoryError). These errors rarely occur and cannot be handled.
  • Exception: Describes errors caused by your program and external circumstances. These errors can be caught and handled.

5.2 Checked vs Unchecked Exceptions

  • Unchecked Exceptions: RuntimeException, Error and their subclasses (e.g., ArithmeticException, NullPointerException, ArrayIndexOutOfBoundsException).
  • Checked Exceptions: All other exceptions. The compiler forces the programmer to check and deal with these exceptions (e.g., IOException, ClassNotFoundException).

5.3 Try-Catch-Finally

  • try: Contains statements that may cause exceptions.
  • catch: Contains statements that handle the exception.
  • finally: Contains statements that always execute on exit of the exception handling (used for cleanup).
try {
    // code that may throw exception
} catch (ArithmeticException e) {
    // handle exception
} finally {
    // always executes
}

5.4 Throw, Throws & Custom Exceptions

  • throw: Used to explicitly throw an exception object from a method or block.
  • throws: Used in the method signature to declare that a method might throw an exception.
  • Rethrowing: Throwing an exception from a catch block to pass it up the call stack (throw e;).

Custom Exceptions: To write a checked exception, extend Exception. To write a runtime exception, extend RuntimeException.

class MyException extends Exception {
    public MyException(String s) {
        super(s);
    }
}

5.5 Concurrency & Threads

Multiple Threads: A thread is a lightweight sub-process that shares memory space.

Creation: By extending the Thread class or implementing the Runnable interface.

Life Cycle States: New, Runnable, Running, Blocked/Waiting, Terminated. (Memorize this for 8-mark questions).
